# Costume Vote — ระบบโหวตประกวดชุด

> สรุปจากแชท "Costume contest voting web application" (16 turns) เพื่อส่งต่อให้ Claude Code ทำเว็บจริง
> ไฟล์ในโฟลเดอร์นี้: `prototype.html` (ต้นแบบล่าสุดที่เล่นได้จริง) · `SPEC.md` (ไฟล์นี้)

---

## 1. เป้าหมาย

เว็บโหวตประกวด costume ตอนงาน outing แทนการใช้กระดาษแบบปีก่อนๆ และ **ออกแบบให้ใช้ซ้ำกับงานอื่นได้**

### Requirement จากผู้ใช้
- Login with Slack (ทุกคนมี Slack)
- **เมเนเจอร์ได้คนละ 10 คะแนน** (ผูกไว้ล่วงหน้า) คนอื่นได้คนละ 1 คะแนน — *เป็นระบบที่ใช้มาตลอด ไม่ต้องปรับสัดส่วน*
- โหวตได้คนละ 1 ครั้ง ยืนยันแล้วแก้ไม่ได้
- **ผู้ประกวดโหวตไม่ได้** (อยู่บนเวที) — จึงไม่มีปัญหาโหวตตัวเอง
- หลังบ้าน host: ดูข้อมูลย้อนหลัง, เพิ่ม/ลบผู้ประกวดหรือทีม, มีฟอร์มให้คนสมัครประกวดเอง
- Dashboard host: ผู้ประกวด, จำนวนผู้โหวต, คะแนนแต่ละคน แบบ real-time
- เก็บผลได้ว่าใครโหวตใคร ใครชนะ — **ความเป็นส่วนตัวไม่ใช่ปัญหา** host เห็นได้หมด
- คะแนนเท่ากันเกิดยาก (คะแนนเมเนเจอร์ดันให้ต่างกัน) — tiebreak ในต้นแบบ: คะแนน → จำนวนโหวต
- จอเวที (โปรเจกเตอร์) **แสดงแค่จำนวนคนโหวต + เวลาที่เหลือ** แล้วมีปุ่ม "เปิดเผยผล" **ทีละอันดับจากท้ายขึ้นมา**

## 2. สถานะต้นแบบ (`prototype.html`)

HTML ไฟล์เดียว state อยู่ใน `localStorage` ซิงก์ข้ามแท็บด้วย `storage` event — ต้องเปลี่ยนเป็น backend จริง

### ฟีเจอร์ที่มีแล้ว (ให้ทำตามนี้ในตัวจริง)
**Login (จำลอง)** — ปุ่ม Slack แล้วเลือกว่าจะเป็นใคร · ข้อมูลตัวอย่าง 30 คน เมเนเจอร์ 6 คน host 2 คน (พี่ต้น, พี่แนน) · ของจริงดึงตัวตนจาก Slack อัตโนมัติ

**สถานะงาน (host คุม):** `registration` (เปิดรับสมัคร) → `voting` (กำลังโหวต) → `closed` (ปิดโหวต) → `revealed` (ประกาศผลแล้ว)

**หน้าโหวต (มือถือ)**
- แสดงสิทธิ์ของตัวเอง "10 คะแนนในฐานะเมเนเจอร์" / "1 คะแนน" + นับถอยหลัง
- grid การ์ดผู้ประกวด (รูป 4:5, ชื่อชุด, ชื่อ+ทีม) แตะเลือก → แถบล่างปุ่ม "โหวต" → **modal ยืนยัน** แสดงรูป+ชื่อ+`+10`/`+1` และเตือนว่าแก้ไม่ได้
- หลังโหวต → **บัตรลงคะแนน (ticket)** มีตราประทับ "ลงคะแนนแล้ว" แก้ไม่ได้
- ถ้าเป็นผู้ประกวด → แจ้งว่าลงคะแนนไม่ได้ · ยังไม่เปิดโหวต → ดูรายชื่อได้ · ปิดแล้ว → แจ้ง

**ฟอร์มสมัครประกวด** — ชื่อที่ให้ประกาศ, ทีม/แผนก, ชื่อชุด/คอนเซปต์, รูปชุด (ย่อเหลือด้านยาว 480px JPEG q0.8 ก่อนเก็บ; ไม่มีรูปใช้ emoji แทน) → สถานะ `pending` รอ host อนุมัติ · ถอนใบสมัครได้ขณะ pending · ผูกกับบัญชี Slack ผู้สมัคร

**หลังบ้าน host — 4 แท็บ**
1. **ภาพรวม** — stepper สถานะ · ตั้งเวลาโหวต (นาที, 1–120, default 5) · เปิดโหวต (ต้องมีผู้ประกวดอนุมัติแล้ว ≥1) · +1 นาที · ปิดโหวตตอนนี้ (มี confirm) · หมดเวลาปิดอัตโนมัติ · เปิดโหวตต่อ +2 นาที · stats 4 ช่อง (ผู้ประกวด/โหวตแล้ว ÷ ผู้มีสิทธิ์/เมเนเจอร์โหวตแล้ว/คะแนนรวม) · กล่องผู้ชนะ · **คะแนนสด** leaderboard มีแถบ · **ตาราง "ใครโหวตใคร"** · คัดลอกผลเป็น CSV (log ทุกโหวต + ตารางอันดับ) · **ปุ่ม ↺ รีเซ็ต** (เลือก "ล้างคะแนนรอบนี้" เก็บผู้ประกวด กลับไป registration / "ล้างทั้งหมด") · ปุ่มจำลองโหวต (demo only)
2. **ผู้ประกวด** — รออนุมัติ (อนุมัติ/ปฏิเสธ) · รายชื่อ (ลบ) · เพิ่มเองโดย host (ผูก Slack หรือไม่ผูกก็ได้ เช่นประกวดเป็นทีม; ถ้าผูก คนนั้นโหวตไม่ได้) · **รายชื่อล็อกหลังเปิดโหวต**
3. **ผู้ใช้และสิทธิ์** — ค้นหา · toggle เมเนเจอร์ (10 คะแนน) · toggle Host (ต้องมี host ≥1) · น้ำหนักคิด ณ ตอนกดโหวต
4. **งานทั้งหมด** — สร้างงานใหม่ · สลับงานที่ active · ดูผลงานเก่า (มีตัวอย่าง "ปาร์ตี้ปีใหม่ 2026 ประกวดชุดไทย") · ลบงาน

**จอเวที (`#stage`)** — ธีมเวทีมีม่านแดง พื้นม่วงเข้ม ตัวเลขทอง
- `registration`: thumbnail ผู้ประกวด + "เปิดเว็บบนมือถือ login Slack รอโหวต"
- `voting`: ตัวเลขใหญ่ "โหวตแล้ว N จากผู้มีสิทธิ์ M" + progress bar + นับถอยหลัง (**ไม่โชว์คะแนน**)
- `closed`/`revealed`: แถวอันดับซ่อนเป็น "?" → host กด **Space / ลูกศรขวา** หรือปุ่ม "เปิดอันดับ N" เปิดจากท้ายขึ้นมา (แอนิเมชันพลิก) → อันดับ 1 มี 🏆 ใหญ่ + confetti · ย้อนกลับได้ · ปุ่มเต็มจอ · หลังเปิดครบมีปุ่ม "รีเซ็ตเล่นใหม่"

## 3. Stack ที่ตกลงกัน (เงื่อนไข: ฟรีทั้งหมด ยกเว้น Cloud Run ที่บริษัทมี + เปิดทิ้งไว้ได้ทั้งปีโดยไม่เสียเงิน)

| ส่วน | ใช้อะไร | ค่าใช้จ่าย |
|---|---|---|
| เว็บและ API | **Next.js (TypeScript)** | ฟรี |
| Login | **Auth.js + Sign in with Slack (OpenID Connect)** | ฟรี |
| รายชื่อและเมเนเจอร์ | **Slack API** sync จาก user group เช่น `@managers` | ฟรี |
| Hosting | **Cloud Run ของบริษัท** — แยก `costume-vote-demo` กับ `costume-vote` | 0 ในโควต้าฟรี |
| ฐานข้อมูล + real-time | **Firestore** (เก็บรูปชุดในเอกสารด้วย) | 0 ในโควต้าฟรี |
| Secrets | **Secret Manager** (3 ตัว: Slack client secret, bot token, session secret) | 0 ในโควต้าฟรี |
| Docker image | Artifact Registry | 0 ถ้าไม่เกิน 0.5 GB |

**ที่ตัดออกแล้วและเหตุผล:** Supabase (บริษัทมี GCP อยู่แล้ว) · **Vercel** (แพลนฟรีห้ามใช้งานบริษัท) · Cloud Storage (เก็บรูปที่ย่อแล้ว ~50–100KB ใน Firestore ได้ เอกสารละไม่เกิน 1MB) · Cloud SQL (ต้องทำ WebSocket เอง)

### Slack App
- OIDC scopes: `openid`, `profile`, `email` · **ตรวจ team ID ตอน login** ให้เข้าได้เฉพาะ workspace บริษัท
- Bot scopes: `users:read`, `usergroups:read` · host กด sync รายชื่อเมเนเจอร์ก่อนเปิดโหวต แล้วแก้มือในหลังบ้านได้
- ผูกเมเนเจอร์ด้วย **Slack User ID** ไม่ใช่ชื่อ

### โครงสร้างข้อมูล Firestore
```
users/{slackId}                       ชื่อ, แผนก, isManager, isHost
events/{eventId}                      ชื่องาน, status, durationMin, endsAt, revealStep, createdAt
events/{eventId}/contestants/{id}     ชื่อ, ทีม, ชื่อชุด, รูป (data URL ย่อแล้ว), status (pending|approved), slackId?
events/{eventId}/votes/{slackId}      contestantId, weight (10|1), at
```
**ใช้ slackId ของผู้โหวตเป็น document ID ของโหวต** → 1 คน 1 โหวตตั้งแต่ระดับฐานข้อมูล กดซ้ำ/เน็ตกระตุกก็ไม่ซ้ำ

### กฎความปลอดภัย
- **ลงคะแนนผ่าน API บน server เท่านั้น** ตรวจใน transaction เดียว: (1) เปิดโหวตอยู่และยังไม่หมดเวลา (2) ยังไม่เคยโหวต (3) ไม่ใช่ผู้ประกวดที่อนุมัติแล้ว (4) **คิดน้ำหนัก 10/1 จากข้อมูลบน server** ไม่เชื่อค่าจากหน้าเว็บ
- Firestore Security Rules: หน้าเว็บอ่านได้อย่างเดียว · เฉพาะ host อ่าน `votes` (ใครโหวตใคร) ได้
- การจัดการงาน/ผู้ประกวด/สิทธิ์ ผ่าน API ที่เช็คว่าเป็น host

### ค่าตั้งที่ทำให้เปิดทิ้งไว้ได้โดยบิล = 0
- Cloud Run **minimum instances = 0** (scale to zero)
- **Billing แบบ request-based** ("CPU is only allocated during request processing") — ห้าม CPU always allocated
- Artifact Registry **cleanup policy** เก็บแค่ 2–3 image ล่าสุด
- **หน้า host กับจอเวที subscribe Firestore ตรงจากเบราว์เซอร์** ไม่ผ่าน Cloud Run (ถ้าผ่าน Cloud Run เปิดจอเวทีค้างไว้ instance จะไม่ปิดและโดนคิดเงิน)
- มือถือผู้โหวต **ไม่ subscribe** — อ่านแค่ตอนเปิดหน้าและตอนโหวต (ประหยัดโควต้าอ่าน: 300 คนยังไม่ถึง 5,000 reads/วัน)
- ตั้ง **budget alert $1/เดือน**
- ใส่ค่าทั้งหมดนี้ไว้ในสคริปต์ deploy เลย ไม่ต้องไปกดในหน้าเว็บ

**สิ่งที่ต้องแลก:** cold start 2–5 วิสำหรับคนแรกหลังไม่มีใครใช้นาน → ให้ host เปิดเว็บไว้ก่อนเริ่มงานสักนาที

### โควต้าฟรีอ้างอิง (ตรวจอีกครั้งก่อนใช้ เพราะอาจเปลี่ยน)
Cloud Run 2 ล้าน req + ~50 ชม. ประมวลผล/เดือน · Firestore 50k reads / 20k writes ต่อวัน + 1GB · Secret Manager 6 secrets + 10k calls/เดือน · Artifact Registry 0.5GB

## 4. ข้อเสนอที่ยังไม่ได้ทำ (ถามผู้ใช้ก่อนถ้าจะทำ)
- หลายหมวดรางวัลในงานเดียว (เช่น ชุดสวยสุด / ชุดฮาสุด) — ผู้ใช้ชอบไอเดียออกแบบให้ใช้ซ้ำ แต่ยังไม่ได้ยืนยันเรื่องหลายหมวด
- QR code บนจอเวทีให้สแกนเข้าเว็บ
- แจ้งพนักงานล่วงหน้าว่า host ดูได้ว่าใครโหวตใคร (ผู้ใช้บอกว่าไม่ซีเรียส แต่ยังเป็นข้อแนะนำที่ดี)

## 6. งานที่ต้องทำต่อ (ลำดับที่แนะนำในแชท)
1. สร้าง Slack App (OIDC + bot scopes ข้างบน)
2. เปิด Firestore + Secret Manager ในโปรเจกต์ GCP เดียวกับ Cloud Run
3. เขียน Next.js ตามต้นแบบ: หน้าโหวต, ฟอร์มสมัคร, หลังบ้าน 4 แท็บ, จอเวที
4. API โหวตแบบ transaction + Security Rules
5. Dockerfile + สคริปต์ deploy ที่ใส่ค่าประหยัดทั้งหมด → deploy เป็น demo
6. ทดสอบกับทีมเล็ก แล้ว deploy service ตัวจริงสำหรับวัน outing
