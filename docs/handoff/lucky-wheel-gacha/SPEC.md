# Matchazuki Lucky Day — วงล้อคู่ + ตู้กาชาปองจับคู่แลกของขวัญ

> สรุปจากแชท "เว็บวงล้อสุ่มสำหรับกิจกรรมบริษัท" (34 turns) เพื่อส่งต่อให้ Claude Code ทำเว็บจริง
> ไฟล์ในโฟลเดอร์นี้: `prototype.html` (ต้นแบบล่าสุดที่เล่นได้จริง) · `sheet-logger.gs` (Apps Script รับข้อมูลลงชีท) · `SPEC.md` (ไฟล์นี้)

## 1. เป้าหมาย

เว็บเดียวสำหรับงาน outing ของบริษัท (TDFB / Matchazuki) **50–100 คน** มี 2 เกมให้เลือกจากหน้าแรก

| เกม | ใช้ที่ไหน | ต้องมี backend ไหม |
|---|---|---|
| **วงล้อคู่** — ซ้ายชื่อพนักงาน ขวาของขวัญบริษัท | จอเวที คนคุมกดเอง | ไม่ต้อง (เบราว์เซอร์ล้วน) |
| **ตู้กาชาปอง** — จับคู่แลกของขวัญ ทุกคนได้ชื่อคนที่ต้องเอาของไปให้ | มือถือทุกคน + หน้าโฮสต์ + จอเวที | ต้องมี (ทุกเครื่องต้องเห็น state เดียวกัน) |

ความต้องการหลักจากผู้ใช้: ใช้งานง่าย สวย **ไม่ใช่ CSS ทรงเรขาคณิตธรรมดา** มีระบบ host ฟรี (ยกเว้น Cloud Run ที่บริษัทมีอยู่แล้ว) และต้อง **แฟร์ โปร่งใส ไม่ล็อกผล** ให้คนทุกวัยเชื่อได้

## 2. สถานะต้นแบบ (`prototype.html`)

- HTML ไฟล์เดียว ~900 บรรทัด ไม่มี framework ไม่มี build step ไม่มี library ภายนอก
- **วงล้อคู่ทำงานครบแล้ว** — แก้รายชื่อ/ของขวัญได้ เก็บใน `localStorage` มีตาราง log + ดาวน์โหลด CSV + ช่องใส่ URL Apps Script
- **กาชาปองเป็น demo** — ซิงก์ข้ามแท็บในเครื่องเดียวผ่าน `localStorage` + `BroadcastChannel` เท่านั้น ต้องเปลี่ยนไปคุยกับ Cloud Run
- มีป้าย "โครงตัวอย่าง · ยังไม่ต่อระบบหลังบ้าน" บน topbar ให้เอาออกตอนทำจริง

## 3. วงล้อคู่ — spec สุดท้ายที่ตกลงกันแล้ว

### Flow
1. กด **"เริ่มหมุน"** → ทั้งสองวงหมุนพร้อมกัน (เห็นชื่อของขวัญวิ่งชัดๆ — **ห้ามมีผ้าคลุมวงขวา**)
2. วงซ้ายหน่วงแล้วหยุดที่ชื่อ (4.2–5.1 วิ) → แสดงชื่อ + พลุเล็ก
3. วงขวา **ยังหมุนค้างไม่หยุด** (`spinFree(0.42)`) → ปุ่มเปลี่ยนเป็น **"หยุดวงล้อของขวัญ"** (สีแดง ume)
4. กดปุ่ม **หรือแตะตรงไหนก็ได้บนจอ** → **สุ่มของขวัญ ณ ตอนกดหยุด** (ไม่ใช่ตอนกดเริ่ม — กันคนเล็งจังหวะ) → หน่วง 2.8–3.5 วิ แล้วหยุด → พลุชุดใหญ่
5. กด **"บันทึกแล้วหมุนต่อ"** → ตัดชื่อ+ของขวัญออกจากวงล้อ → เพิ่ม log → ส่งเข้า Google Sheet → พร้อมหมุนรอบใหม่

### การหมุนและการหยุด (สำคัญ — ผ่านการลองผิดลองถูกมาแล้ว)
- easing แบบ ease-out quartic `1-(1-p)^4` หมุน 4–6 รอบก่อนหยุด
- **หยุดแล้วต้องหยุดเลย** ไม่เด้ง ไม่ไหลกลับ ไม่ค้างคาช่องข้างๆ — ผู้ใช้ย้ำว่า *"สุ่ม = สุ่ม"*
- ตำแหน่งจอดสุ่มภายในช่องเล็กน้อย โดยจอด **เลยแนวบนไปทางขวาเสมอ** `(0.07 + rand*0.32) * seg` เพื่อไม่ให้ตัวหนังสือพลิกด้านตอนวินาทีสุดท้าย
- เข็มเป็น SVG นิ่งอยู่ด้านบน
- **เสียงติ๊ก** (Web Audio, square wave 1500→380 Hz ~55ms) ดังทุกครั้งที่ช่องข้ามเข็มระหว่างหมุน มีปุ่มเปิด/ปิด จำค่าไว้

### ❌ สิ่งที่ลองแล้วผู้ใช้ปฏิเสธ — ห้ามใส่กลับ
| ลองอะไร | ทำไมไม่เอา |
|---|---|
| ผ้าคลุมวงล้อของขวัญ แตะเพื่อเปิด | มองไม่เห็นว่าหมุนอยู่จริงไหม |
| หมุดรอบวง + เข็มดีด (ทั้งแบบ SVG ลอยและวาดใน canvas) | ดูแปลก ไม่สมจริง |
| จังหวะ "ค้างคาหมุด" ถอยกลับแล้วฝืนข้าม | เข็มหยุดที่ "ตั้ม IT" แล้วไหลไป "นุ่น" → ดูเหมือนโกง |

> ตัวเลือกที่เสนอไว้แต่ยังไม่ได้ทำ: จำลองฟิสิกส์จริง (ปล่อยให้ฟิสิกส์ตัดสินผล) หรือใส่แรงเฉื่อยให้เข็มแกว่งเบาๆ — ไม่ต้องทำ เว้นแต่ผู้ใช้ขอ

### ป้ายข้อความบนวงล้อ
- วางแนวรัศมี; **ครึ่งวงซ้ายพลิก 180°** ให้อ่านไม่กลับหัว
- จัดทุกบรรทัด **กึ่งกลางกันเอง** (ไม่ชิดขอบนอก) เว้นระยะไม่ทับดุมกลาง (`maxw = R - hub - 26`)
- ลดขนาดตัวอักษรก่อน (ต่ำสุด 11px) แล้วค่อยตัดบรรทัด สูงสุด 3 บรรทัด ตามความกว้างช่องจริง
- **ตัดบรรทัดแบบสมดุล** (dynamic programming ลด squared slack) ไม่ใช่อัดบรรทัดแรกให้เต็ม
- **ตัดคำไทยด้วย `Intl.Segmenter('th', {granularity:'word'})`** ตัดเฉพาะรอยต่อคำก่อน → ถ้าไม่ได้จริงๆ ค่อยตัดกลางคำ
- กฎตัดกลางคำ: ห้ามแยกสระบน/ล่าง/วรรณยุกต์ออกจากพยัญชนะ, ห้ามทิ้ง เ แ โ ใ ไ ท้ายบรรทัด, ห้ามแยก ำ
- ช่องว่างที่ผู้ใช้พิมพ์เองมี priority สูงสุด (cost × 0.35) · ไม่ปล่อยตัวอักษรเดี่ยวลอยบรรทัดสุดท้าย · จุดไข่ปลาเป็นทางสุดท้ายเท่านั้น
- ผลที่ต้องได้: `เซ็ตมัทฉะ / พรีเมียม` · `กระติกเก็บ / ความเย็น` · `บัตรเติม / น้ำมัน 500฿` (ไม่ใช่ `พรีเมี / ยม`)
- คำนวณ layout ครั้งเดียวตอน `setItems` / resize ไม่คำนวณทุกเฟรม และวาดใหม่หลัง `document.fonts.ready`

### สีช่องวงล้อ
`['#4E7A2E','#C9A227','#2C3E6B','#8DBE4A','#B5334A','#2E6B63']` — สีตัวอักษรเลือกตาม luminance (`0.299r+0.587g+0.114b > 138` → `#16261E` ไม่งั้น `#FFF`) ถ้าจำนวนช่อง `n % 6 === 1` ให้ช่องสุดท้ายใช้สี index 2 กันสีชนช่องแรก

## 4. ตู้กาชาปอง — spec

### Flow พนักงาน (มือถือ)
สแกน QR → ใส่ชื่อ เช่น `เบนซ์ (GM)` (ถ้าชื่อซ้ำในห้อง เตือนให้ใส่ทีมต่อท้าย, เทียบแบบไม่สนตัวพิมพ์) → หน้ารอ เห็นตู้ + จำนวนคนในห้อง → เมื่อโฮสต์กดสุ่ม **ทุกเครื่องเล่นแอนิเมชันพร้อมกันเท่ากัน 3–5 วิ** (ตู้สั่น 1.5 วิ → แคปซูลตก 1 วิ → แคปซูลโยก 1.4 วิ → แคปซูลแตก) → แสดง "เอาของขวัญของคุณไปให้ **[ชื่อ]**" + พลุ

### Flow โฮสต์
เห็นรายชื่อเข้าห้องแบบ real-time เป็น chip ลบได้ · นับจำนวน · ต้องมีอย่างน้อย 3 คน · กดสุ่มได้ครั้งเดียวต่อรอบ · ปุ่มเริ่มห้องใหม่ · กันคนเข้าห้องเพิ่มหลังสุ่มแล้ว

### กติกาจับคู่
ไม่ได้ชื่อตัวเอง · ไม่มีชื่อซ้ำ · ทุกคนให้และได้รับคนละ 1 → ใช้ **Sattolo's algorithm** (สับเป็นวงกลมวงเดียว คนที่ i ให้ของคนที่ i+1) **คำนวณที่ server ครั้งเดียว** แต่ละเครื่องอ่านแค่ช่องของตัวเอง

### ความโปร่งใส (ผู้ใช้ให้ความสำคัญมาก — ผู้ใหญ่บางคนกังวลว่าระบบล็อกผลได้)
แนวทางที่คุยกันและผู้ใช้เห็นด้วย ให้ทำทั้งหมดนี้:

**ก่อนสุ่ม**
- จอเวทีแสดงรายชื่อทุกคน + ตัวเลขใหญ่ "64 คน" → ถามว่าครบไหม → **กดล็อกห้องต่อหน้าทุกคน** (ไม่มีใครเข้าเพิ่มได้)
- ประกาศกติกา "สุ่มครั้งเดียว ไม่สุ่มใหม่"

**ตอนสุ่ม**
- ความสุ่มมาจาก **ลูกเต๋าจริง** ที่คน 2–3 คนต่างแผนก/ต่างวัยทอยบนเวที → โฮสต์กรอกเลขลงระบบ → เลขทุกชุดขึ้นจอตัวใหญ่
- ให้ผู้ใหญ่ที่กังวลที่สุด (หรือพนักงานใหม่อายุน้อยสุด) เป็นคนกดปุ่ม ทีมทำเว็บไม่แตะอะไรเลย
- **ทุกเครื่องเปิดผลพร้อมกัน รวมถึงโฮสต์** → ⚠️ ต้องเอาตาราง "ผลจับคู่ทั้งหมด" (`#h-pairs`) ออกจากหน้าโฮสต์ในต้นแบบ
- จอเวทีแสดงชื่อทุกคนเรียงเป็นวงกลมสลับที่ไปมา 3–5 วิแล้วนิ่ง

**หลังสุ่ม**
- จอเวทีขึ้นตรวจกติกาอัตโนมัติ 3 ข้อพร้อม ✓ : ไม่มีใครได้ชื่อตัวเอง / ทุกคนได้ชื่อไม่ซ้ำ / ทุกคนให้และได้รับคนละ 1 ชิ้น
- รายชื่อที่ล็อก + เลขลูกเต๋าค้างบนจอ + **QR ไปหน้า "ตรวจผลด้วยตัวเอง"** ที่กรอกรายชื่อกับเลขไว้ให้แล้ว กดคำนวณเทียบได้ทันที
- (ถ้าเป็นแลกของแบบเปิดเผย) โชว์วงกลมทั้งวงพร้อมลูกศร ใช้เป็นลำดับเดินแลกของได้
- แชร์ Google Sheet แบบ view-only ให้ HR/ผู้ใหญ่ (มี Version history เป็นหลักฐาน)
- ห้ามโชว์ hash / ศัพท์ "อัลกอริทึม" เป็นข้ออ้างหลัก — ความเชื่อใจมาจากการเห็นกระบวนการ

**รองรับคนที่ใช้มือถือไม่คล่อง:** โต๊ะลงชื่อ + โฮสต์เพิ่มชื่อแทนได้ + (ถ้าแลกแบบเปิดเผย) จอเวทีบอกผลทุกคนได้โดยไม่ต้องพึ่งมือถือ

**ประโยคประกาศบนเวที:** *"ลูกเต๋าเป็นคนสุ่ม ระบบแค่เอาผลลูกเต๋าไปจัดคนเป็นวงกลม แล้วให้แต่ละคนเอาของไปให้คนถัดไป ใครสงสัยเอาเลขไปคำนวณเองได้ ได้ผลเดียวกันทุกครั้ง"*

### สูตรสุ่มที่ตรวจสอบได้ (ใช้ทั้งที่ server และหน้าตรวจผลเอง — โค้ดต้องเหมือนกันเป๊ะ)
ผลขึ้นกับ **รายชื่อที่ล็อก + เลขจากลูกเต๋า** เท่านั้น — รายชื่อเดิม + เลขเดิม = ผลเดิมทุกครั้งบนทุกเครื่อง โค้ดนี้สั้นพอขึ้นจอได้ทั้งก้อน

```js
async function สุ่มวงกลม(รายชื่อ, เลขจากคนในงาน) {
  // 1) เรียงตามตัวอักษร ไม่มีใครจัดลำดับเองได้
  const วง = [...รายชื่อ].sort((a, b) => a.localeCompare(b, 'th'));
  let ครั้งที่ = 0;
  const สุ่ม = async () => {
    // 2) ตัวเลขสุ่มมาจากเลขที่คนในงานพูด + รายชื่อทั้งหมด เท่านั้น
    const ข้อมูล = new TextEncoder().encode(`${เลขจากคนในงาน}|${วง.join(',')}|${ครั้งที่++}`);
    const ลายนิ้วมือ = new Uint32Array(await crypto.subtle.digest('SHA-256', ข้อมูล));
    return ลายนิ้วมือ[0] / 2 ** 32;
  };
  // 3) สลับที่ให้เป็นวงกลมวงเดียว ไม่มีใครติดตัวเอง
  for (let i = วง.length - 1; i > 0; i--) {
    const j = Math.floor((await สุ่ม()) * i);
    [วง[i], วง[j]] = [วง[j], วง[i]];
  }
  // 4) แต่ละคนให้ของคนถัดไปในวง
  return วง.map((ชื่อ, i) => [ชื่อ, วง[(i + 1) % วง.length]]);
}
```
> ข้อควรระวัง: `localeCompare` ต้องให้ผลตรงกันระหว่าง Node บน server กับเบราว์เซอร์ — ทดสอบให้แน่ใจ (หรือ normalize/เรียงด้วย collator ที่กำหนด locale ชัดเจน)

### ❓ คำถามที่ยังไม่ได้คำตอบ — ต้องถามผู้ใช้ก่อนทำส่วนนี้
**แลกของแบบเปิดเผย หรือแบบลับ (Secret Santa)?**
- เปิดเผย → โชว์เลข + วงกลมทั้งวง + หน้าตรวจผลได้ทันทีหลังสุ่ม
- ลับ → ใครรู้เลข+รายชื่อคำนวณผลทุกคนได้ ต้องเก็บเลข/วงกลมไว้ก่อน แล้วเปิดเผยหลังแลกของเสร็จ (ยังตรวจได้ แค่ตรวจทีหลัง)

## 5. Stack ที่ตกลงกัน

| ส่วน | ใช้อะไร | หมายเหตุ |
|---|---|---|
| หน้าเว็บ | HTML + CSS + JavaScript ธรรมดา | ไม่ใช้ React ไม่มี build step |
| วงล้อ | Canvas 2D | วาดเอง |
| ตัดคำไทย | `Intl.Segmenter` | มีในเบราว์เซอร์ |
| พลุ / เสียง | Canvas + Web Audio API | เขียนเอง ไม่โหลดไฟล์เสียง |
| QR code | qrcode.js (~5KB) | library ภายนอกตัวเดียว |
| ฟอนต์ | Chonburi (หัวข้อ) + Anuphan (เนื้อหา) | Google Fonts |
| Backend | **Node 20 + Hono บน Cloud Run** | ~150 บรรทัด เสิร์ฟทั้ง static + API จาก origin เดียว (ไม่ต้อง CORS) |
| Real-time | **SSE** (ไม่ใช่ WebSocket) | HTTP ธรรมดา ผ่าน wifi โรงแรมได้ดีกว่า |
| สถานะห้อง | Memory ของ server (`Map`) | ข้อมูลมีอายุชั่วโมงเดียว ไม่ต้องมี DB |
| บันทึกผล | **Google Sheet ผ่าน Apps Script** (`sheet-logger.gs`) | 2 แท็บ: วงล้อคู่ / กาชาปอง |
| สำรอง | เก็บในเครื่องก่อนเสมอ + retry + ปุ่ม "ส่งเข้าชีทอีกครั้ง" + CSV | เน็ตล่มเกมไม่ค้าง |
| Excel | Sheet → Download → .xlsx | ไม่ต่อ Microsoft Graph |

**Endpoints ขั้นต่ำ:** เข้าห้อง (join) · ดูสถานะห้อง · โฮสต์ล็อกห้อง/สั่งสุ่ม (รับเลขลูกเต๋า) · SSE stream

**ใครเขียนลงชีท:** วงล้อคู่ = เบราว์เซอร์ (แถวละครั้งตอนกดหมุนต่อ) · กาชาปอง = **Cloud Run เขียนทีเดียวทั้งชุด** ตอนสุ่ม (มือถือแก้ผลเองไม่ได้ และไม่เกิด 80 requests ชนกัน)

**Deploy:**
```bash
gcloud run deploy <service> --source . --region asia-southeast1 \
  --min-instances=1 --max-instances=1 --allow-unauthenticated
```
- `--max-instances=1` **สำคัญที่สุด** — state อยู่ใน memory ถ้าแตกหลาย instance แต่ละเครื่องจะเห็นห้องคนละใบ
- `--min-instances=1` กัน cold start 3–5 วิ (คิดเงิน ~$5–8/เดือนถ้าเปิดทิ้ง → แนะนำ deploy ก่อนงาน 1 วัน ลบหลังงาน)
- ใช้ Buildpacks ไม่ต้องเขียน Dockerfile

## 6. ⚠️ จุดที่ต้องแก้จากต้นแบบ (เจอตอนสรุป)
1. `sendToSheet()` ในต้นแบบส่ง `{time,name,gift}` — **ไม่มี `secret` และ `type`** แต่ Apps Script ต้องการ → ต้องส่ง `{type:'wheel', secret, name, gift, round}`
2. ต้นแบบใช้ `mode:'no-cors'` จึงอ่าน response ไม่ได้ → ตั้ง `sent=true` ทั้งที่ชีทอาจตอบ `unauthorized` → ถ้าต้องการรู้ผลจริง ให้ยิงผ่าน Cloud Run แทน (และไม่ต้องฝัง SECRET ในหน้าเว็บที่ใครก็เปิดดูได้)
3. เอาตาราง `#h-pairs` (โฮสต์เห็นผลก่อน) ออก — ขัดกับหลักความโปร่งใส
4. เอาป้าย "โครงตัวอย่าง" บน topbar ออก

## 8. งานที่ต้องทำต่อ (ลำดับแนะนำ)
1. ถามผู้ใช้เรื่องแลกของเปิดเผย/ลับ (ข้อ 4)
2. เขียน server Node 20 + Hono: rooms ใน memory, join/lock/draw/SSE, สูตรสุ่มแบบ seed, เขียนชีทจาก server
3. แก้หน้ากาชาปองให้คุยกับ server จริง + หน้าจอเวทีกาชาปอง (ล็อกห้อง, ใส่เลขลูกเต๋า, วงกลมสลับชื่อ, ตรวจกติกา 3 ข้อ, QR)
4. หน้า "ตรวจผลด้วยตัวเอง" (static, ใช้สูตรเดียวกัน, ทำงานได้แม้ไม่ใช้เว็บเรา)
5. QR code บนหน้าโฮสต์สำหรับให้พนักงานสแกนเข้าห้อง
6. แก้ payload ชีทของวงล้อคู่ + retry/ปุ่มส่งซ้ำ
7. ทดสอบ: 80+ แท็บพร้อมกัน, เน็ตหลุดระหว่างสุ่ม, ชื่อซ้ำ, ไทยยาวๆ บนวงล้อ

**สิ่งที่ผู้ดูแลต้องทำเอง:** วาง Apps Script แล้ว Deploy (~10 นาที) · รัน `gcloud run deploy` (~5 นาที) · ใส่ URL · ลบ service หลังงาน
**ของบนเวที:** ลูกเต๋าจริง 2–3 ลูก · โปรเจกเตอร์ · โต๊ะลงชื่อ · ซ้อมกับผู้ใหญ่ที่กังวลก่อนวันงาน · ทดสอบ wifi สถานที่จริง + hotspot สำรองให้เครื่องโฮสต์
