# PRODUCT — Party Challenge (มุมมอง PO)

> เอกสารนี้คือ "ความจริงล่าสุด" ของโปรเจกต์ — ถ้าขัดกับ `docs/handoff/*` ให้ยึดไฟล์นี้

## 1. Vision
เว็บเดียวสำหรับงานกิจกรรม (ใช้ซ้ำได้ทุกงาน ไม่ผูกกับงานเอาท์ติ้ง) เปิดจากมือถือ/โน้ตบุ๊ก/จอเวทีได้หมด รวม 2 โมดูล
| โมดูล | เกม | ใครใช้ |
|---|---|---|
| **Lucky Zone** | วงล้อคู่ (ชื่อ ↔ ของรางวัล) · ตู้กาชาปองจับคู่แลกของขวัญ | คนคุมเวที + พนักงานทุกคน |
| **Fashion Vote** | โหวตประกวดชุดตอน Fashion Walk | พนักงานทุกคน (มือถือ) + host + จอเวที |

**Success metrics วันงาน**
- คนโหวตได้ภายใน 30 วินาทีหลังสแกน QR (ไม่ต้องถามใคร)
- 0 ข้อร้องเรียนเรื่อง "ระบบล็อกผล"
- รองรับ 100 คนพร้อมกันโดยไม่ค้าง · ผลทุกเกมเก็บลงชีท/CSV ได้ครบ

### 3.1 คำแนะนำ PO สำหรับ Q1–Q2 (2026-11-13)
**Q1 → แลกของแบบเปิดเผย**
- จุดที่ผู้ใหญ่กังวลคือ "ระบบล็อกผล" — แบบเปิดเผยตรวจได้ **ทันทีบนเวที** (เลขลูกเต๋า + วงกลม + ตรวจกติกา 3 ข้อ) ตรงกับสคริปต์พิธีกรใน `docs/copy.md`
- แบบลับต้องซ่อนเลขลูกเต๋าไว้ก่อน (ใครรู้เลข+รายชื่อคำนวณผลทุกคนได้) → ความโปร่งใสต้องรอหลังแลกของเสร็จ ขัดกับสคริปต์ที่บอกว่า "ตรวจเองได้เลย"
- แลกของกันในงานทันทีอยู่แล้ว ความลับจึงอยู่ได้แค่ไม่กี่นาที · จอเวทีบอกผลทุกคนได้ ช่วยคนที่ใช้มือถือไม่คล่อง · ใช้วงกลมเป็นลำดับเดินแลกของได้ (สนุกบนเวที)
- ถ้าอนาคตอยากเล่น Secret Santa (ส่งของล่วงหน้าหลายวัน) ค่อยเพิ่มเป็นตัวเลือกในหลังบ้าน — โครงสูตรสุ่มเดิมรองรับ

**Q2 → พิมพ์ชื่อเอง (ตอนนี้)**
- Slack login ยังไม่มีจนกว่าจะขึ้น Google Cloud (Phase 2b ถูกเลื่อนไปช่วงนั้น) → พิมพ์ชื่อทำให้กาชาปองเล่นได้ก่อน
- กันชื่อซ้ำด้วยการเตือน + แนะนำใส่ทีมต่อท้าย · host เพิ่ม/ลบชื่อแทนคนที่ไม่ถนัดมือถือได้ · host ล็อกห้องต่อหน้าทุกคนก่อนสุ่ม
- ออกแบบให้สลับเป็น Slack login ได้ทีหลังโดยไม่ต้องแก้ส่วนสุ่ม
- ⚠️ ข้อจำกัดเดียวกับ Fashion Vote: ระหว่างยังไม่มี Firestore ห้องกาชาปองซิงก์ได้แค่หลายแท็บในเครื่องเดียว (ใช้ทดลอง/ซ้อม) — เล่นจริงหลายมือถือต้องรอขึ้น Google Cloud
